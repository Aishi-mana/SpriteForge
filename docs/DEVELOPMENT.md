# Development guide

## Setup and running

```
python -m venv .venv && .venv\Scripts\activate            (Windows)
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt
python -m engine.main            # http://127.0.0.1:8765   (spriteforge.bat does all of this + the Tauri window)
```
The UI is served by the engine: edit `ui/index.html` and reload (Ctrl+R in the browser; in the Tauri window press F5 / reopen). Python changes need an engine restart.

## Tests (no GPU, no network)

```
python tests/run_all.py          # 435+ checks, ~1 minute; needs numpy, pillow, scipy (+ node for the JS tests)
python tests/test_rig.py         # or any single file
```
- `tests/_common.py`: helpers (`ok`, `done`, synthetic sprites `synth_sprite()` / `hero_sprite()`, `Up` fake upload, `install_fastapi_stubs()`).
- **Models are faked**: `engine.generate.inpaint` / `.generate` are replaced by functions with the *same positional signature* that paint predictable pixels (see `test_templates.py`, `test_api.py`).
  When you change a model-call signature, update the fakes.
- `test_api.py` calls endpoint **functions directly**. Without fastapi/pydantic installed, tiny stubs are installed (`install_fastapi_stubs`); with them installed the same tests run against the real classes. The helper `A(fn, **kw)` fills unspecified Form/File params from a defaults table.
- `tests/js/*.js` extract code from `ui/index.html` (the PXE block, the editor block, the option helpers) and run it under `node` against a fake DOM/canvas. `test_ui.py` also checks that every `$('id')` exists and the script parses.
- What tests cannot cover: real SDXL output quality, VRAM use, speed, the real browser / Tauri window, Godot/Unity import. See `TESTING_CHECKLIST.md`.

## Adding things

**An endpoint**: add a `def` to `engine/main.py` with `@app.get/post/delete("/api/...")`, Form/File params (multipart) or a pydantic model (JSON), raise `HTTPException(400, "readable message")` for input errors, wrap model calls (`500` + OOM hint).
Add it to `tests/test_api.py` (call the function; add any new Form param names to the `DEF` table). The API table in `docs/ARCHITECTURE.md` was generated by scanning the `@app.*` decorators; regenerate it when routes change.

**A tab** (UI): (1) button `<button id="tN" onclick="tab(N)">` and add N to the `[1..N].forEach` list in `tab()`; (2) sidebar panel `<div id="p-x" class="hide">` and `show('p-x', n==N)`;
(3) a card in `<main>` + `show('card', n==N)`; (4) if it uses the shared generation controls add `||n==N` to `show('p-gen', ...)`; (5) extend the `$('go').textContent=[...]` array; (6) sidebar controls with unique `id`s are saved automatically;
non-input state (images, rigs) needs explicit save/load: add the field to `saveProject()` and `loadProject()` in the UI and a passthrough in `projects.save/load` (images use the `images` dict, JSON uses `doc[...]`); (7) tests.

**A clip**: add the name to `rig.CLIPS` (and `ONE_SHOT` if it plays once, `CLIP_PAD` if it needs a bigger canvas), write its branch in `rig._sem` (semantic channels: `dx dy rot torso head au_L/R al_L/R lu_L/R ll_L/R`; attack-style clips use the `wu wl ou ol legF legB kF kB` channels + `__attack` marker),
add it to the UI `anim` select, `ANIM_DEF`, the `CLIPS` array, and a test that it keeps its pixels. Death needs the `rot` channel (whole-body tilt about the feet).

**An export format**: extend `exporter.export_pack` (it receives per-entry frames + pivot and the layout plan); add an option to `xopts()` in the UI and a checkbox; test regions/pivots.

**Patching `ui/index.html`** (it is ~125 KB, long lines): use a small Python script with `assert old in text` + `str.replace(old, new, 1)`, then re-run `tests/test_ui.py`. Never replace a substring that is part of a larger token (an `async function` once became `async const`).
After any edit: the script must parse (`node --check`), and every `$('id')` must exist.

## Lessons learned (things that bit us)

1. **Test with realistic data.** The model classifier passed tests with simplified tensor names and then flagged every real SDXL file as "not SDXL" (real SDXL contains `transformer_blocks`). Check real markers first; block only what you can *positively* identify; label the rest.
2. **DOM semantics**: an `<option>` without a `value` attribute uses its text as its value, so decorating `option.text` corrupted the value. Always set `value` explicitly. (`tests/js/options_test.js` models this.)
3. **Continuous pixel coordinates** (pixel *i* spans [i, i+1)): joints belong to `floor(x)`; mirror a pivot as `width - x`; Python's `round()` is banker's rounding - use the deterministic `_floor_half`.
4. **Never drop pixels silently**: painted secondary parts that are not simulated (switch off, too small) must fall back to a body bone; unlabeled stray outline pixels from `ImageDraw` must take the nearest label.
5. **Overlap dilation near pivots only**, or neighbouring colours smear along limbs.
6. **Dither and recolour in a perceptual space** (OKLab/OKLCH); hue shifts must reduce chroma to stay in the sRGB gamut instead of clipping (clipping shifts lightness).
7. **Averaging makes muddy pixel art**: quantise first, then take the dominant colour per cell; sample with nearest.
8. **8 GB VRAM**: UNet + ControlNet together OOM -> sequential offload; reference (IP-Adapter) pipelines fit with model offload. Drop the cached pipeline after any failure.
9. **Side/overlapping views break nearest-bone assignment** (arms over torso): supply exact overrides (dummies know them) or let the user paint.
10. **Clean upscales can be detected at half the true grid** (sub-harmonic): prefer the largest multiple that keeps ~all the edge energy.
11. **The build sandbox has no GPU/network, and can reset** (files vanish; only delivered zips survive - it happened twice). Keep every change in a deliverable; the full-project zip is the source of truth.
12. Untested-on-hardware code (model loading, IP-Adapter, ControlNet, inpaint) is where first-run errors appear: log clearly, return readable errors, and let Diagnostics expose them.

## Release convention used so far

Each change = a zip of **only the changed/new files** + a `PHASEn.md` note (later moved to `docs/phases/`), named `spriteforge_phaseN_topic.zip`, delivered to the user, who unzips over the project and relaunches.
Hotfixes: `spriteforge_phaseN.1_HOTFIX-...`. `config.json` is never shipped (it holds the user's paths). Rust changes need `spriteforge.bat rebuild`.
