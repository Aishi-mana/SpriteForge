# Phase 41 — Multi-bone skinning and weight painting

In Custom rig, load a source and fit a connected skeleton. Choose Smooth multi-bone mesh (legacy profiles remain rigid by default). Auto binding calculates normalized vertex weights from segment distances: up to four closest bones, controlled by blend radius (1–50% of longer canvas side). Mesh resolution 8–64 cells per axis (limited by source dimensions); default 48. Select any bone, paint its target weight 0–100% with smooth radial falloff, strength 0–100% and radius 1–75% of longer canvas side. The remaining influence is redistributed proportionally, with automatic fallback when removing the only influence. Manual paint can introduce any of the up to 32 bones; total influence remains one. Later stamps apply in sequence. Selected-bone heatmap is generated from backend mesh weights and interpolated for display on the source; it updates after a stroke or refresh. Undo last stamp, clear selected bone's stamps, or reset all to auto binding. Limit 256 stamps per rig. Delete a subtree removes stamps targeting its deleted bones. Changing geometry/source affects auto binding and does not transform normalized paint coordinates; review after edits.

Render custom pose uses linear blend skinning of mesh vertices through the custom parent-child pose transforms, inverse triangle sampling using the existing softmesh rasterizer, nearest for pixel art or premultiplied bilinear for HD. Zero rotation preserves the original image exactly. The same image/pose export, gallery and reference workflows remain. Weights, mesh settings and skeleton save in project and portable JSON preset. Rigid mode keeps paint available for later switching. Existing humanoid and modular render paths are preserved. CPU only; bounded mesh, stamp count and existing surface budget. Large meshes and many stamps may be slow; mesh folds, texture stretching and occlusion errors can remain. This is not dual-quaternion skinning, cloth physics, multi-layer custom-rig attachment, an animation timeline or IK. Heatmap is interpolated visualization rather than per-pixel exact weight painting.

Regression tests cover normalized auto/paint weights, three-plus-bone influence, erase redistribution, rest identity, weighted vs rigid poses, heatmap and project persistence, malformed stamps. JS parse and literal IDs checked. CI workflow now triggers on feature branch pushes as well as pull requests, so future phases can be validated before merge. CPU run and live browser/device validation remain pending until verified.
