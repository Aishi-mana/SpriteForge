# Phase 48 — Batch character production

Production tab: capture current Generate settings (checkpoint, LoRA, style, size, sampler and finishing). Common prompt plus 1–24 named character descriptions. One image per job; fixed consecutive seeds (random base resolved once for -1). JSON recipe import/export keeps settings and descriptions; verify installed models when reusing. Server validates all rows and model/LoRA compatibility before adding to existing persistent single-worker generation queue. Capacity check and grouped submission under worker lock. Batch groups derive from retained job metadata, show latest attempt per character, progress/errors, cancel and retry with same resolved seed; existing history retains originals subject to normal pruning/clear. Finished result can be reviewed and explicitly saved as new project, never overwrite an existing project. New project contains reference and custom-rig source only; fit skeleton/weights manually. This does not claim automatic fitting or identity consistency.

Batch export selected 1–24 saved custom rig projects sequentially in UI. Use each project's own timeline (optional verified AI cleanup) or auto-map another project's motion via Phase 45; destination geometry/weights/source untouched. Retarget warnings block export until explicit review/retry; use individual retarget editor for manual mappings. Unique run folder for each export prevents replacement. Fixed untrimmed PNG atlas, metadata, optional GIF/frames. Stop after current project and retry waiting/failed/review rows. Export result status is session-only; generated files persist. Existing GPU queue is sequential; no new worker or parallel inference, direct generation remains available. CPU-only tests cover recipe planning, batch history/error recovery, motion transfer/export and project preservation; actual inference and browser checks separate.
