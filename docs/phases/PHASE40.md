# Phase 40 — Custom skeleton and bone hierarchy editor

New Custom rig tab. Import an image (max 1024 px per side), use an existing reference/Animate source/modular composite or send a generated result. Load a starter humanoid, side-view quadruped, winged humanoid or chain skeleton. Starter coordinates are normalized to the canvas, not fitted by AI. Drag tail joints or root head, select a bone, rename it, add child bones, reparent to a non-descendant, delete a subtree or edit its local rotation. Root remains unique; child heads coincide with their parent's tail. Stable IDs are separate from display names. Maximum 32 bones, no disconnected/cyclic or zero-length bones. Reset rotations returns to rest pose. JSON preset import/export preserves normalized endpoints, hierarchy, names, sampling and current pose; source image stored separately in project. Existing projects load safely without a custom rig.

Render custom pose performs actual CPU rigid cutout skinning by nearest rest bone segment, applying inherited parent and local rotation matrices. Pixel nearest or HD bicubic sampling. Preview shows transformed joints; export transparent posed PNG, save to project gallery or use as a reference. A padded canvas allows rotation outside rest bounds, subject to allocation guard (48 million output surface-pixels across bones). Rendering order is parent-first; this is not yet manual multi-bone skinning, IK, custom-rig animation timeline, per-bone z ordering or modular attachment integration. Extreme bends can show seams/overlap. Standard humanoid Animate, custom keyframes, Modular and runtime exports unchanged. Regression tests added for preset validation, parent-child connectivity, zero-pose identity, malformed tree rejection and project persistence. CPU CI must pass before merge; device/browser validation remains separate.
