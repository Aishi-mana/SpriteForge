# Phase 31 — Modular character customization

New Modular tab is a CPU-only, non-destructive 2D compositor. Import transparent body/base, outfit, shoes, front/back hair, accessories or other assets. Use the character master, appearance candidate, Reference sprite or generated result as a body base. First source defines canvas size (16–1024 px). Each source is retained; per-layer position, scale, opacity, horizontal mirror, visibility and ordering affect only the composite. Body import hides previous body alternatives. Wear only this category hides other alternatives in that category; normal visibility supports multiple accessories. The stack is bottom to top; default import order puts back hair behind the body and front hair/accessories above clothing. Adjust order manually. Pixel nearest or HD Lanczos sampling. Layers are clipped to canvas, not stretched to fit. No GPU or additional dependencies.

Save the project to retain layers and transforms. Export a ZIP containing composite PNG, original layer PNGs, manifest and portable recipe.json. Extract recipe.json and import it in another project to reuse the same assets. Download an individual source PNG. Send the flattened composite to Reference or Animate, or save to gallery. The earlier master, candidate and approved directional views are not modified. Limits: 24 layers, 1024 px per source side, 16 million source pixels and 24 MB encoded normalized assets per recipe. Invalid recipes rejected before replacing project recipe. No semantic extraction, automatic outfit fitting or body completion: importing a complete sprite retains existing hair/clothes, so separately prepared transparent layers work best. Animation currently uses a flattened composite and existing rig; layers do not independently follow bones. GPU/browser integration unverified; CPU regression tests added. Tile and terrain unchanged.
