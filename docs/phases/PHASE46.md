# Phase 46 — Multi-character animation scenes

New Scenes tab. Compose up to eight independent animated actors and static props on a shared transparent canvas (16–1024 px per side, 2–64 scene frames, 1–60 FPS). Add current custom timeline or a saved character project's custom timeline without opening/modifying it. Optional accepted cleanup is baked only after fingerprint verification; stale saved cleanup reports an error, disable cleanup and retry. Actor clips contain 1–32 untrimmed PNG frames, original timing, sampling and pivot, no live rig dependency. Import/export actor clip bundles and portable scene JSON. PNG imports use bottom-center pivot. Project saves retain scene snapshots; old projects load empty scenes. Encoded actor data limited to 24 MB and decoded aggregate 24M source frame pixels. Each actor has stable ID, editable name, start/end position (linear interpolation through active interval), scale 10–200%, horizontal flip about pivot, opacity, depth (higher is front, equal uses list order), visibility, inclusive scene frame range, source frame offset, speed 10–300%, loop/hold/hide on source completion. Scene FPS and actor FPS sampled independently using integer frame index; source cells fixed. Hide outside active range. Actors composited with RGBA alpha, clipped to scene bounds. Nearest pixel or smooth HD per source. Position refers to clip root-head pivot for custom timeline and bottom-center for imported static PNG, not necessarily feet. Use start=end position for stationary actors. Shared track overview and scrub, explicit render current frame/full scene, cached playback, loop/one-shot. Exports via standard exporter with fixed untrimmed scene frame cells, center pivot, atlas JSON and Godot/Unity metadata, optional GIF and individual frames. Exports flattened, not separately controllable runtime actors. Scene render preview 12M output pixels, export 32M, bounded scaled surfaces and cache. No collision, automatic combat, audio, camera tracks, live rig instances or automatic character interaction. Use authored positions, facing, visibility and timing to compose interaction previews. No GPU required. CPU regressions cover independent timing, position, depth, clipping/flip/opacity, snapshot, project persistence and export budgets. UI syntax/IDs checked; Windows/Linux validation and actual interactive testing pending.
