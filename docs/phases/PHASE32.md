# Phase 32 — AI-assisted modular asset generation

In Modular, import a visible body base, choose a reference-capable model, and open AI-assisted asset generation. Select outfit, footwear, front/back hair, accessory or other, describe the item and choose the base's viewing angle. Reference source can be the visible body layer(s) or the current assembled character. Qwen Rapid uses native reference conditioning, NetaYume uses its existing image-to-image route and SDXL uses IP-Adapter. The modular-asset prompt asks for an isolated detachable item, not another whole character. All existing LoRA compatibility and runtime checks apply. Pixel canvas forces pixel style; HD uses chosen art style (anime fallback). One generation at a time; same GPU lock and local worker memory lifecycle; no extra models or downloads.

The result is border-keyed against a solid background, cropped and fitted without stretching into an approximate region inferred from the visible body bounding box. Background choice and tolerance are adjustable. Empty or unkeyed opaque results are rejected. This is not semantic segmentation, pose detection, garment extraction, or exact fitting. The AI may reproduce a full character or unsuitable geometry; the raw image, isolated layer and proposed composite are shown for inspection. Neta's image-to-image route can struggle to remove the source character. Change reference influence, prompt or model and regenerate as needed. Existing clothing/hair baked into a base cannot be removed by adding a layer. The accessory region defaults near the upper body and may need manual positioning. Front/back hair and footwear can need manual alignment. Generated variants are not independently rigged.

Accept explicitly to insert the candidate as a separate layer, optionally hiding other layers of that category. Existing layers are never deleted or repainted. Reject/discard or download candidate PNG without accepting. Recipe changes invalidate acceptance until regeneration, so a candidate cannot be added against a different base or placement. Accepted assets persist through the existing modular project/ZIP recipe; unaccepted candidates are temporary. One candidate retained at a time; 24-layer and source-pixel/encoded-size budgets enforced. Tests cover isolated prompt, region sizing, keying, non-destructive preview and missing base. GPU generation and browser integration require live validation.
