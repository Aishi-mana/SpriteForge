# Phase 43 — Inverse kinematics and foot locking

In Custom rig, select a child bone (lower arm, shin, tail segment), add IK from selected bone. Its parent is the upper bone. Up to eight two-bone chains, no shared controlled bones. Select chain, enable/disable, choose positive/negative bend, strength 0–100%, minimum/maximum unsigned bend angle 0–179 degrees. Targets are normalized to source canvas and can extend from -50% to 150%. Drag on the solver canvas or enter coordinates. Gold indicates controlled segments; green target; pink residual line for nonzero error. The canvas shows actual solved joint geometry, not a live textured mesh. Geometry updates after releasing the pointer. Render custom pose to see actual pixels. Solver preserves segment lengths and connected joints, uses analytic two-link geometry in source pixel coordinates, solves ancestors before descendants and reports endpoint residuals in pixels. Full strength replaces the two local rotation angles for an enabled chain; partial strength blends with manual or keyed rotations. No mutation of stored bone angles.

Create a timeline and select Current timeline frame target scope. Set or drag a target to create/update a key at the scrubbed frame, select outgoing linear/ease/step interpolation, delete a key. Unkeyed intervals hold endpoints. Choose a start/end inclusive frame range and lock at the currently solved endpoint. Each range stores a fixed canvas-space point, overriding target keys in that range. Locks cannot overlap on one chain; remove them to edit locked targets. A reachable target with full strength remains fixed even if ancestors rotate; constrained or unreachable targets show residual error. This is manually authored foot contact, not automatic ground detection, automatic root translation, collision detection, gait generation or world-space game-engine foot IK. The root pivot stays fixed as in Phase 42. Contact boundaries may need surrounding target keys for smooth transitions. No generalized chain solver, per-bone absolute angle limits or IK for the existing Modular renderer.

Manual pose uses base targets, while timeline render evaluates bone tracks, target tracks and contact overrides, then IK before rigid or weighted skinning. Same solver used for single-frame preview and baked sheet export. IK-only clips allowed when they contain target keys or contact ranges. Existing allocation bounds remain. Delete a chain removes its keys/locks; deleting subtree removes associated chains; reparenting a controlled lower bone requires removing its chain first. Clip shortening trims contacts and drops later keys after confirmation; deleting clip clears IK timeline keys/locks but preserves base targets. Presets and projects store all constraints and contacts; old profiles without IK unchanged. CPU only.

Regression tests cover target reach, segment lengths, bend direction, unreachable error, fixed contacts, IK-only clips, weighted deformation, project persistence and invalid overlapping chains/contacts. UI syntax and literal ID checks performed; CPU CI and actual interactive browser validation pending.
